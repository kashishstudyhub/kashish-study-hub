1. 🔗 Data Link Layer

The Data Link Layer is the second layer of the OSI reference model. It provides communication over a direct link between neighbouring network devices.

It receives packets from the Network Layer and organizes them into frames for transmission over the link.

Main Functions

  • Framing
  • Flow Control
  • Error Control
  • Reliable link-level delivery
  • Managing communication over a link
Exam Point:

The three major functions emphasized in this unit are Framing, Flow Control and Error Control.

2. ⚙️ Data Link Layer Services

The Data Link Layer provides services to the Network Layer and handles communication over the underlying physical link.

Important Services

  • Framing: Divides the bit stream into frames.
  • Flow Control: Controls the rate at which frames are sent.
  • Error Control: Detects and handles transmission errors.
  • Link Management: Helps manage communication between directly connected devices.
Simple Example:

Suppose one computer wants to send data to another computer. The Data Link Layer packages the data into frames and helps control and protect the transfer over the link.

3. 🧩 Framing

Framing is the process of dividing a continuous stream of bits received from the Network Layer into manageable units called frames.

Why is Framing Required?

  • Identifies the beginning of a frame.
  • Identifies the end of a frame.
  • Allows the receiver to process data frame by frame.
  • Supports error detection and control.

Common Framing Approaches

  • Character count
  • Byte stuffing
  • Bit stuffing

Character Count

In character-count framing, a field indicates the number of characters contained in the frame.

Byte Stuffing

Byte stuffing inserts special escape bytes when data contains a byte pattern that could otherwise be interpreted as a frame delimiter.

Bit Stuffing

Bit stuffing inserts an extra bit into the transmitted bit stream when a particular sequence of consecutive bits occurs, helping distinguish data from frame delimiters.

Remember:

Framing = Bit stream ko frames me divide karna.

4. 🚦 Flow Control

Flow control is a mechanism that regulates the rate of data transmission so that a sender does not overwhelm a receiver.

Need for Flow Control

  • Receiver may process data more slowly than the sender.
  • Prevents excessive buffering at the receiver.
  • Helps maintain efficient communication.

Common Flow Control Techniques

  • Stop-and-Wait
  • Sliding Window

Stop-and-Wait Flow Control

The sender transmits one frame and waits for an acknowledgement before sending the next frame.

Example:

Sender → Frame 1 → Receiver

Receiver → ACK → Sender

Sender → Frame 2 → Receiver

Sliding Window Flow Control

Sliding Window allows multiple frames to be transmitted before receiving acknowledgements for all of them.

5. ❌ Error Control

Error control is concerned with detecting transmission errors and recovering from them when necessary.

Main Components

  • Error detection
  • Acknowledgements
  • Sequence numbers
  • Retransmission
  • Timers

Error Detection

Error detection techniques allow the receiver to determine whether the received frame has been corrupted.

Acknowledgement

An acknowledgement informs the sender about successful receipt of a frame or data.

Retransmission

If a frame is lost or corrupted, the protocol can request or trigger retransmission.

Sequence Number

Sequence numbers help identify frames and support correct ordering and duplicate detection.

Easy Formula:

Error Control = Detection + ACK + Sequence Number + Retransmission

6. 📡 Elementary Data Link Protocols

Elementary data link protocols are basic protocols used to explain how frames can be transmitted reliably over a data link.

Main Ideas

  • Sending frames
  • Receiving frames
  • Acknowledgements
  • Flow control
  • Error recovery

These basic protocols provide the foundation for understanding more advanced protocols such as sliding window protocols.

7. ⏸️ Stop-and-Wait Protocol

In Stop-and-Wait, the sender sends one frame and waits for an acknowledgement before sending the next frame.

Working

  1. Sender sends a frame.
  2. Receiver receives the frame.
  3. Receiver sends an acknowledgement.
  4. Sender receives the acknowledgement.
  5. Sender sends the next frame.

Advantages

  • Simple to understand.
  • Simple implementation.
  • Provides basic flow control.

Disadvantages

  • Can be inefficient on long-delay links.
  • Sender may remain idle while waiting for acknowledgement.

8. 🪟 Sliding Window Protocol

Sliding Window is a flow and error control technique that allows multiple frames to be in transit at the same time.

Basic Concept

The sender maintains a window containing frames that it is allowed to transmit. As acknowledgements are received, the window moves forward.

Simple Example:

Window initially: [1] [2] [3] [4]

After acknowledgement of frame 1: [2] [3] [4] [5]

This movement is called sliding of the window.

Advantages

  • Allows multiple frames in transit.
  • Improves link utilization.
  • Supports flow control.
  • Can support error recovery.

9. 🔄 Go-Back-N Protocol

Go-Back-N is a sliding-window error-control protocol. It allows multiple frames to be transmitted before acknowledgements are received.

Working

  1. Sender transmits a sequence of frames.
  2. If a frame is lost or damaged, the receiver detects the problem.
  3. The sender retransmits the affected frame and subsequent outstanding frames according to the protocol.
Example:

Frames sent: 1 → 2 → 3 → 4 → 5

If frame 3 requires retransmission, the sender may retransmit: 3 → 4 → 5

Advantages

  • Relatively simple implementation.
  • Uses pipelined transmission.

Disadvantage

Correctly received frames after the problematic frame may need to be retransmitted, causing additional traffic.

9.5️⃣ Selective Repeat Protocol

Selective Repeat is a sliding-window protocol that retransmits only the frames that are missing or received incorrectly.

Working

  1. Multiple frames are transmitted.
  2. Receiver can accept correctly received frames.
  3. Incorrect or missing frames are identified.
  4. Only required frames are retransmitted.
Example:

Frames sent: 1 → 2 → 3 → 4 → 5

Suppose frame 3 is lost. Only frame: 3 needs retransmission, while correctly received frames can be retained.

Advantages

  • Reduces unnecessary retransmissions.
  • Efficient when errors are relatively infrequent.

Disadvantage

  • More complex than Go-Back-N.
  • Receiver needs additional buffering and management.

10. 📊 Go-Back-N vs Selective Repeat

Feature Go-Back-N Selective Repeat
Retransmission Affected frame and subsequent outstanding frames may be retransmitted Only required frames are retransmitted
Complexity Lower Higher
Efficiency Can be lower when errors occur Can be higher when errors occur
Buffering Relatively simpler Requires more receiver buffering
