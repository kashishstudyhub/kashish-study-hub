1. 🚚 Transport Layer

The Transport Layer is the fourth layer of the OSI reference model. It provides communication services between application processes running on different hosts.

Main Functions

  • Process-to-process communication
  • Segmentation and reassembly
  • Flow control
  • Error control and reliability
  • Connection management
  • Congestion control
Exam Point:

Transport Layer provides end-to-end communication services between applications/processes.

2. ⚙️ Transport Layer Services

The Transport Layer accepts data from applications and provides appropriate transport services for communication with the destination process.

Important Services

  • Process-to-process delivery
  • Reliable data transfer when supported by the protocol
  • Flow control
  • Connection management
  • Congestion control

3. 📡 UDP

UDP stands for User Datagram Protocol. It is a connectionless transport protocol.

Characteristics

  • Connectionless
  • Low protocol overhead
  • Does not provide TCP-style reliable delivery
  • Does not perform connection establishment
  • Suitable for applications where low overhead is important

UDP Working

  1. Application gives data to UDP.
  2. UDP places the data into a datagram.
  3. The datagram is passed to the IP layer.
  4. The destination host receives the datagram.
Easy Meaning:

UDP = Simple, connectionless transport with low overhead.

4. 🧾 UDP Header

A UDP header contains four main fields.

Field Purpose
Source Port Identifies the sending application port.
Destination Port Identifies the receiving application port.
Length Indicates the length of the UDP datagram.
Checksum Used for error detection.
Remember:

UDP Header = Source Port + Destination Port + Length + Checksum

5. 🔒 TCP

TCP stands for Transmission Control Protocol. It is a connection-oriented transport protocol.

Main Characteristics

  • Connection-oriented
  • Reliable data transfer
  • Ordered delivery
  • Flow control
  • Congestion control
  • Uses acknowledgements and sequence numbers
Simple Example:

Sender → TCP → Network → TCP → Receiver

TCP helps ensure that data is delivered reliably and in the correct order.

6. 🧾 TCP Header

TCP uses a larger header because it provides several control and reliability features.

Field Purpose
Source Port Identifies the sending application.
Destination Port Identifies the receiving application.
Sequence Number Helps identify the position of data in the byte stream.
Acknowledgement Number Indicates the next byte expected by the receiver.
Header Length Indicates the size of the TCP header.
Control Flags Used for connection and control functions.
Window Size Used for flow control.
Checksum Used for error detection.
Urgent Pointer Provides information for urgent data when applicable.

Important TCP Flags

  • SYN
  • ACK
  • FIN
  • RST
  • PSH
  • URG

7. 🤝 TCP Connection Management

TCP establishes a connection before normal data transfer and terminates it when communication is finished.

Three-Way Handshake

TCP commonly establishes a connection using a three-step handshake.

  1. Client sends SYN.
  2. Server responds with SYN + ACK.
  3. Client responds with ACK.
Easy Diagram:

Client → SYN → Server

Client ← SYN + ACK ← Server

Client → ACK → Server

Connection Established ✔

Connection Termination

TCP uses control messages to close the connection in an orderly manner.

8. ✅ TCP Reliability

TCP provides reliable byte-stream delivery using several mechanisms.

Main Mechanisms

  • Sequence numbers
  • Acknowledgements
  • Retransmission
  • Checksum
  • Timers

Sequence Numbers

Sequence numbers identify positions of bytes in the TCP byte stream and help the receiver maintain the correct order.

Acknowledgements

Acknowledgements allow the receiver to inform the sender about successfully received data.

Retransmission

When TCP determines that data may have been lost, it can retransmit the required data.

9. 🚦 TCP Flow Control

TCP flow control prevents a fast sender from overwhelming a receiver that has limited available buffer space.

Window-Based Flow Control

TCP uses the receiver's advertised window to indicate how much additional data the receiver is currently prepared to accept.

Simple Example:

Receiver Window = 5000 bytes

The sender uses this information to control how much unacknowledged data it can have in transit.

10. 🚦 TCP Congestion Control

Congestion occurs when the offered traffic exceeds what the network can handle effectively.

TCP uses congestion-control mechanisms to regulate the amount of data injected into the network.

Important Concepts

  • Congestion Window (cwnd)
  • Slow Start
  • Congestion Avoidance
  • Fast Retransmit
  • Fast Recovery

Slow Start

TCP begins with a relatively small congestion window and increases the sending rate as acknowledgements arrive, subject to the algorithm's rules.

Congestion Avoidance

After reaching an appropriate threshold, TCP changes its growth behavior to increase the congestion window more cautiously.

Fast Retransmit

TCP can retransmit a segment before a normal retransmission timer expires when sufficient duplicate acknowledgements indicate that a segment may be missing.

11. ⏱️ TCP Timer Management

Timers help TCP determine when data may need retransmission if an expected acknowledgement does not arrive in time.

Retransmission Timer

TCP uses a retransmission timer associated with outstanding data. If the timer expires before the expected acknowledgement is received, TCP may retransmit the relevant data.

Why Timers are Important?

  • Helps recover from packet loss.
  • Prevents indefinite waiting for acknowledgements.
  • Supports reliable communication.
Remember:

TCP Timer → Wait for ACK → Timeout → Possible Retransmission

12. 📊 UDP vs TCP

Feature UDP TCP
Connection Connectionless Connection-oriented
Reliability Does not provide TCP-style reliable delivery Provides reliable byte-stream delivery
Ordering No TCP-style ordered byte-stream delivery Ordered byte-stream delivery
Flow Control No TCP-style flow control Yes
Congestion Control No TCP-style congestion control Yes
Overhead Lower Higher
Connection Setup Not required Required
