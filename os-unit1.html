1. Introduction to Operating System

Definition:

An Operating System (OS) is system software that manages computer hardware and provides services and an interface for users and application programs.

The operating system acts as an important interface between the user, application programs and computer hardware.

Simple View:

User → Application Programs → Operating System → Hardware

Examples of Operating Systems

  • Windows
  • Linux
  • macOS
  • Android
  • iOS

2. Purpose of Operating System

The operating system provides an environment in which users and programs can use computer resources efficiently.

Main Purposes

  • Managing hardware resources.
  • Providing an interface between user and computer.
  • Managing programs and processes.
  • Managing files and storage.
  • Controlling input and output devices.
  • Providing protection and security mechanisms.
  • Making computer resources easier to use.
Exam Point:

The OS works as a resource manager as well as a control program for the computer system.

3. History & Evolution of Operating Systems

Operating systems developed gradually as computer hardware and user requirements became more advanced.

Early Computer Systems

Early computers had little or no operating-system support. Programs were often prepared and executed with direct interaction with the machine.

Batch Processing

As systems developed, jobs could be collected and processed in batches. This reduced the need for continuous manual intervention.

Multiprogramming

Multiprogramming allowed multiple programs to reside in memory so that the processor could work on another program when one program was waiting for I/O.

Time-Sharing

Time-sharing systems allowed multiple users or tasks to interact with the computer by giving each a small amount of processor time.

Modern Operating Systems

Modern operating systems support multitasking, networking, security, graphical interfaces, multiprocessing and many other features.

4. Generations of Operating Systems

Generation / Period Main Development
Early Systems Limited operating-system support and manual operation.
Batch Systems Jobs were collected and processed in batches.
Multiprogramming Systems Multiple programs could be kept in memory.
Time-Sharing Systems Interactive use by multiple users became possible.
Modern Systems Multitasking, networking, security, multiprocessing and advanced interfaces.

5. Types of Operating Systems

1. Batch Operating System

A batch operating system processes a collection of jobs together without requiring continuous interaction with the user during execution.

2. Time-Sharing Operating System

A time-sharing system provides processor time to multiple users or tasks in small time intervals, supporting interactive use.

3. Multitasking Operating System

A multitasking operating system allows multiple tasks to make progress by sharing processor time.

4. Multiprogramming Operating System

Multiprogramming keeps multiple programs in memory so the CPU can switch to another ready program when the current program waits.

5. Real-Time Operating System

A real-time operating system is designed for systems where responses need to be produced within specified timing constraints.

6. Distributed Operating System

A distributed operating system works in an environment containing multiple networked computers and aims to coordinate resources and activities across the system.

7. Network Operating System

A network operating system provides services that support computers connected through a network, including resource sharing and network-related management.

Type Main Idea
Batch Jobs processed in batches.
Time-Sharing Interactive sharing of processor time.
Multitasking Multiple tasks make progress.
Multiprogramming Multiple programs kept in memory.
Real-Time Timing constraints are important.
Distributed Coordinates resources across multiple computers.
Network Provides network-related services and resource sharing.

6. Characteristics of Operating Systems

An effective operating system should provide useful facilities for users and efficient management of computer resources.

Desirable Features

  • Convenience for users.
  • Efficient resource management.
  • Reliability.
  • Security.
  • Protection.
  • Ability to support multiple programs or users where required.
  • Good performance and responsiveness.
  • Ease of maintenance and administration.

7. System Protection & Security

System Protection

System protection refers to mechanisms that control access to system resources and help prevent one process or user from interfering improperly with another.

System Security

System security protects the computer system and its information against unauthorized access and other security threats.

Common Protection and Security Mechanisms

  • User authentication.
  • Access control.
  • File permissions.
  • Process isolation.
  • Resource access restrictions.
  • Protection of system resources.
Difference:

Protection mainly controls access to resources within the system, while security broadly deals with protecting the system and its information from unauthorized access and threats.

8. Operating System Architecture

Operating system architecture describes how the components of an operating system are organized and how they interact.

System Programmer's View

From a system programmer's perspective, the operating system is a collection of components and mechanisms that manage hardware, processes, memory, files, I/O and other resources.

User's View

From the user's perspective, the operating system provides an interface and services that make the computer convenient to use.

User ↓ Application Programs ↓ Operating System ↓ Hardware

9. Layered & Monolithic Systems

Monolithic System

In a monolithic operating-system design, many core operating-system services operate together as a large kernel.

Advantages

  • Direct communication between components can be efficient.
  • Good performance can be achieved.

Disadvantages

  • Large and complex kernel structure.
  • Changes to one component may be harder to isolate.

Layered System

A layered operating system divides functionality into layers. Each layer provides services to the layer above it and uses services provided by the layer below it.

+-----------------------+ | User Programs | +-----------------------+ | System Services | +-----------------------+ | File Management | +-----------------------+ | Memory Management | +-----------------------+ | Process Management | +-----------------------+ | Hardware | +-----------------------+

Advantages of Layered Design

  • Clear organization.
  • Easier testing and debugging.
  • Better separation of responsibilities.
  • Changes can often be localized to appropriate layers.

10. Operating System Services

The operating system provides services to users and application programs.

Major Services

  • Program execution.
  • Input/Output operations.
  • File-system manipulation.
  • Communication.
  • Error detection.
  • Resource allocation.
  • Protection and security.
Service Purpose
Program Execution Loads and executes programs.
I/O Operations Provides controlled access to input and output devices.
File Management Supports creation, deletion, reading and writing of files.
Communication Supports communication between processes or systems.
Error Detection Detects and handles various system errors.
Resource Allocation Allocates processor, memory and other resources.
Protection Controls access to system resources.

11. Utility Programs

Utility programs are system-support programs that provide useful facilities for managing, maintaining or using a computer system.

Examples of Utility Functions

  • File management.
  • Backup and restore.
  • Disk management.
  • System monitoring.
  • Text editing.
  • Compression and archiving.
Remember:

Utility programs support the operation and maintenance of a computer system but are distinct from the core kernel functions of the operating system.

12. System Calls

Definition:

A system call is a controlled interface through which a user program requests a service from the operating system.

Why are System Calls Used?

  • To request operating-system services.
  • To access files.
  • To create or control processes.
  • To perform input/output operations.
  • To communicate with other processes or system components.

Common Categories

Category Examples of Operations
Process Control Create, terminate and control processes.
File Management Open, read, write and close files.
Device Management Request and release devices or perform I/O.
Communication Exchange information between processes.
Protection Control access permissions and resources.
Simple Flow:

Application Program → System Call → Operating System → Hardware

13. Spooling

Definition:

Spooling stands for Simultaneous Peripheral Operations On-Line. It is a technique in which data for a device is temporarily stored, commonly on secondary storage, so that devices and programs can operate more efficiently.

Example

Printing is a common example. Print jobs can be placed in a queue and processed by the printer as the device becomes available.

Application ↓ Print Queue / Spool ↓ Printer

Benefits

  • Helps manage slow peripheral devices.
  • Allows jobs to wait in a queue.
  • Improves coordination between programs and devices.

14. Buffering

Definition:

Buffering is the temporary storage of data in a memory area called a buffer while data is being transferred between components operating at different speeds.

Why is Buffering Used?

  • To handle speed differences between devices and processors.
  • To reduce waiting during data transfer.
  • To improve I/O efficiency.
  • To smooth data transfer between components.
Input Device ↓ Buffer ↓ CPU / Program

Spooling vs Buffering

Spooling Buffering
Often uses a queue for device-related jobs. Uses temporary memory storage during data transfer.
Commonly associated with slower shared peripheral devices. Commonly handles differences in data-transfer rates.
